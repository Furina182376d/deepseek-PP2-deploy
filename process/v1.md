# 排查记录 v1 — Kimi-K3 PP=3 TP=8 三节点 (2026-08-21)

## 现象
- decode 恒 5.9~6.2 t/s (TPOT 161~174ms),与上下文长度无关 (512→16384),
  冷/暖 Triton 缓存均不变 (昨天 161-169ms vs 今天 169ms)
- prefill 冷缓存 6~23 t/s (JIT 编译风暴,2048 异常点 606s);
  **暖缓存后 116 t/s (2.9s/336tok) → prefill 已修复,是 JIT 问题**
- 24×H20,decode 仍远低于健康值 (健康参考:单 token decode 应 ~5-10ms)

## 已确认事实
1. **decode 瓶颈是稳态的**:暖缓存对 decode 无效 → 不是 JIT 编译,是每步真实的
   内核执行时长。TPOT 与 ctx 无关 → 不是 attention/KV 增长,是**固定数量的
   每层小内核序列**。
2. **dmon 实证 (decode 期 174s)**:三节点**同时** GPU busy (n0 95%、n1 98%、
   n2 66-71%),mem ~1%,FLOPs ~0 → 机制① GPU-busy 胜出,② GPU 空闲排除。
   "高占用+无内存+无算力" = 大量微型内核背靠背执行的指纹。
3. KDA/conv1d Triton 内核编译后单次 0.044/0.045ms (快,非瓶颈)。
4. MoE:896 experts,top-16-of-50,MXFP4,SM90 → **MARLIN** backend
   (fused_marlin_moe + moe_align_block_size)。
5. CUDA graph: FULL_AND_PIECEWISE + VLLM_USE_BREAKABLE_CUDAGRAPH=1,
   GDN 层 @eager_break_during_capture → decode 时 GDN 层每步 eager。
6. 19:10 "快跑" 异常已破案:非快跑,进度条显示 prefill 31 t/s + output 0.77 t/s,
   与暖缓存下正常速度一致,decode 从未快过。
7. 模型加载+初始化 ~5 分钟/次 (62.5GB/卡),warmup gen 有 JIT 拖尾 (~200s 冷)。

## 通信不是瓶颈 — 三层证据

### 证据 1:物理上限 (带宽+延迟算术)
每 decode 步 PP 跨节点通信量 = 1 token × hidden 7168 × 2B = 14KB/跳 × 2 跳
(stage1→2→3)。实测 RTT 0.02ms (ICMP 0.18ms)。按最保守 1Gbps 链路:
28KB ÷ 125MB/s + RTT ≈ **0.3ms/步**,占 170ms 的 <0.2%。
返回 logits 同链路 ~500KB/步,同样毫秒级。网络物理上不可能解释现状。

### 证据 2:dmon 行为论证 (最有力)
瓶颈 = 某一环节在排队等待;若网络是瓶颈,节点 GPU 应**空闲等数据**
(dmon 低 sm%)。实测 decode 期间三节点**同时 95%+ busy**,没有一个节点
在等 —— GPU 全在执行本地内核。且三节点同时忙说明节点间无互相阻塞的
同步等待 (若串行阻塞,duty 应 ~33%)。

### 证据 3:一致性检验
- 通信量/步不随 ctx 变 (每步仍是 1 token 的 hidden) → 与 TPOT 恒定一致 ✓
- 缓存状态改变翻天覆地 (prefill 6→116 t/s),decode 纹丝不动 ✓
- prefill 流水线传输 ~9.4MB/2.9s = 3.2MB/s 有效速率,链路远未饱和 ✓

### 边界 (诚实声明)
- **以上仅排除跨节点 PP 通信。TP 节点内 NVLink 通信 (每层 all-reduce +
  MoE all-to-all,31 层×每步) 尚未单独量化**,是 170ms 嫌疑人之一,待
  profiler 中 NCCL 内核计时直接回答。
- 无 PP=1 vs PP=3 对照实验 (现有运行全为 PP=3);若 TPOT 不随 PP 变可
  彻底钉死,目前靠物理+行为证据,置信度高但非直接测量。

## 时间分解
```
170ms/步 ≈ GPU 内核执行 ~165ms (dmon 95%) + 引擎调度/采样 ~ms
           + PP 跨节点通信 <1ms + TP 节点内通信 (待测)
```
- 3 个 PP stage 串行 57ms/stage 或全流水并发 165ms/stage —— **未定,待 trace**
- prefill 每 token 8.6ms (暖缓存,已正常)

## 结论
- 瓶颈在**本地稳态内核执行**:每步固定数量的小内核序列共 ~165ms GPU 时间。
- 具体是哪些内核 (MoE MARLIN 小 GEMM 启动 / TP 通信 / KDA eager 分发 /
  其他) **未知,是唯一剩余空白**。
